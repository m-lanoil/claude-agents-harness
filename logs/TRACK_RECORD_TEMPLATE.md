# Track-record log (template)

Copy this file to `logs/TRACK_RECORD.md` (gitignored) and add one row per task outcome. Your log is your own record; the tracked repo holds only this template, so field changes and clearer definitions belong here. Gaps a log exposes in a worker or a rule go through `workers/WORKER_GAP_PROTOCOL.md`.

| Date | Task type | Worker chain | Baseline | Baseline estimate | Claims fixed | How found | Used as deliverable | Human touchpoints | Handed off | Extension needed | Recurrence | Error cost | Owner time | Eval result | Harness issues |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

Field values: Task type is a short free-text description of what the task was, with a parenthetical for detail. Examples, not a closed list: research brief, code from docs, multi-source investigation, structured document, tool extension, enforcement change, bug fix. Use whatever describes the task. Baseline is by hand, plain Claude, or not done. Claims fixed is the number of unsupported or training-data claims corrected (0, 1-3, 4+). How found is harness flag, own reading, or source check. Used as deliverable is yes, partly, or no. Human touchpoints is where the owner intervened: source evaluation, scope or framing, acceptance, or other, with a rough count per category (for example "source 2, acceptance 1"). Handed off is how much of the task the owner did not touch: none, some, or most. Extension needed is whether the task needed a new tool or worker: no, yes (loop followed), or yes (loop skipped). Recurrence is whether a correction repeats a gap already fixed through the Worker Gap Protocol: no, yes, or unsure. Error cost is the brief-time rating from `workers/MODE_SELECTION_PROTOCOL.md` (Error cost section), confirmed by the owner: low or high; use "not recorded" if not rated. Harness issues is free text with no client detail. Baseline estimate is the owner's estimate, in minutes, of how long the baseline would take, given at brief time; "n/a" when the baseline is not done. Owner time is the owner's rough active minutes across the whole task (briefing, running sessions, reviewing, deciding; not waiting), given at hop close. Both are "not recorded" for entries before 2026-11-07. Eval result is the outcome of a sampled baseline eval, as `preferred: harness|plain|neither; claims fixed h/p; minutes h/p` (see `workers/BASELINE_EVAL_PROTOCOL.md`); "declined" when an eval was offered and the owner declined; "n/a" when the task was not sampled or no eval was due.

Entries are added by the log's owner, or by the Meta-Orchestrator with the owner's explicit approval, and must be sanitized of client details. A hop-close step should propose an entry.
